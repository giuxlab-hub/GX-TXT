Problem addressed

On the unmodified dev-108, repeating an action on the same restricted C++ Viewer may compile viewer.so again even when the underlying project has not changed.

Expected behavior

  • Reuses a previous compiled release binary only when all recorded project, source, design, SDK, compiler, policy, adapter and backend fingerprints match.
  • An actual compilation attempts to emit COMPILE START and a completion/failure message to the controlling terminal, with a project-local log fallback.
  • Explicit Build/Export and debugger builds are excluded from the cache. Each new Viewer runtime project can legitimately compile once.

Install only on unmodified dev-108

Close GX-TXT, first roll back any previous v1 patch, unpack the downloaded ZIP in a separate folder and execute these commands from that folder:

ROOT="$HOME/gxtxt/gxtxt_pipeline_v09810dev_108"
python3 backport.py --check "$ROOT"
python3 -m unittest -v test_patch
python3 backport.py --apply "$ROOT"

Verify after restart

After restarting from a terminal, repeat an unchanged action on the same Viewer. A cache hit should not produce a new COMPILE START. If no terminal output is available, inspect the relevant project log.

tail -f "/path/to/viewer-project/derived/viewer_compilation.log"

Restore original dev-108

Use the exact ROLLBACK command printed by the installer. The original file is preserved under .gxtxt_patch_backups; a later unrelated edit makes rollback refuse the overwrite.

Validation and security limitations

  • Exactly the original dev-108 source is required; the installer refuses other versions or any modified target. All dev-109 and later revisions are incompatible by design.
  • Six isolated unit tests passed; the live Debian GUI/Clang recompilation behavior has NOT been verified.
  • Project-local build receipts and binaries are not cryptographically authenticated against malicious authors; use this optimization only with trusted Viewer projects.
