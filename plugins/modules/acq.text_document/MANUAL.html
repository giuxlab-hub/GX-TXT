1. Install and import

Install acq.text_document_1.0.4.zip using Modules → Install plugin.... Select Text and Source Code Import in Acquisition. Requires GX-TXT 0.9.8.10 or later and the framework-configured Python 3.10+. The implementation uses only Python’s standard library; there is no pip dependency or viewer/module dependency. Later framework releases are permitted by the package descriptor but have not been tested by this delivery.

  1. Create/open a Session, or let the normal acquisition workflow create one.
  2. Select a source with Browse..., or add several with Add sources.... Files may have any extension, or no extension.
  3. Review the read-only Preview and edit the Dataset IDs in the ordinary batch table.
  4. Leave Language override and Encoding on auto unless a particular input requires an explicit choice.
  5. Import enabled sources. Each file becomes one independent Dataset; no merge, numerical column mapping or primary Dataset is required.
  6. To add scripts later, add new Pending rows and use the ordinary import-into-current-Session action.

In the Variables workspace, select the imported Dataset and open Metadata.... Inspect or edit code.language and add fields such as project.purpose, project.component or code.entry_point. User fields are not overwritten by reading a preview. Save the Session normally.

Overrides apply to all rows imported in the current run, not just the highlighted row. For a mixed Python/Tcl batch, keep Language on auto. Import files requiring the same legacy encoding together, then restore Encoding to auto. The pre-import Preview and import both use the current Encoding and Language settings. The imported Dataset records the effective setting.

Choose Import as Auto, Text document or Source code independently from the detected or selected Language. The same Python file may be imported as document.text or code.source; detected Python remains recorded in metadata. The standard acquisition controls offer Copy into Session (default) or Keep/reference original for RAW. For a referenced RAW source, use Dataset Metadata → Verify RAW source... to report OK, SOURCE MODIFIED or SOURCE MISSING.

2. Language and encoding detection

Language selection is ordered: explicit import override, recognized shebang/interpreter, editor modeline, specific content signature where applicable, special filename or extension, then unknown. A content signature may resolve an ambiguous extension such as .m or identify a script saved as .txt. Special filenames take precedence over suffixes, so CMakeLists.txt is recognized as CMake. A shell launcher that explicitly re-execs Tcl is recognized without executing it.

Examples: analysis.py → python, module.tcl → tcl, an extensionless file beginning with #!/usr/bin/env python3 → python, Makefile → make. A generic .m file is matlab-octave unless stronger hints identify Octave or Objective-C. A generic .h is c-cpp. The candidate list and the evidence are retained. Confidence labels describe the rule used, not a probability of correctness. Language identification is not syntax validation.

Encoding auto-detection uses a UTF-8/16/32 BOM when present, the Python coding cookie for recognized Python sources, and otherwise strict UTF-8. UTF-8 also covers ordinary ASCII files. For undecodable legacy input, choose an explicit Encoding such as cp1252 or iso-8859-1. BOM-less UTF-16/32 needs the explicit byte order. The importer does not silently guess a legacy charset or replace invalid characters.

Source Preview may label an undecodable file an encoding candidate so it can reach the import settings. That is not successful text validation: import validates the whole file with the selected encoding and fails on invalid bytes, conflicting BOM or binary/control-heavy content.

3. Dataset contracts and metadata

document.text stores plain text, markup and configuration documents. code.source specializes document.text for source-code languages. Formats are text and source_code, not csv. Both are file-shaped Datasets with no fabricated scientific variables. Even a JSON/CSV-looking input is retained as a document; this importer does not extract its values into a numerical table.

4. Original bytes and read-only preview

RAW and canonical source bytes are preserved exactly: no re-encoding, newline normalization, tab replacement, trimming, syntax repair, dependency collection or code execution. The useful original extension is retained where it is a safe suffix; the complete original filename remains metadata. Original filesystem timestamps, permissions and executable bits are not a backup contract.

Preview scans at most 256 KiB and displays at most 80 lines / 12,000 source characters. Counts explicitly indicate sample or full scope. The entire file is streamed and validated on import; only the preview is bounded. In the read-only snippet, line endings are displayed consistently and control/bidirectional formatting characters are escaped. Those display-only changes never affect the stored source.

For example, a Python source with a # coding: cp1252 header stays CP1252: it is not rewritten to UTF-8 while retaining a now-incorrect coding cookie. Windows CRLF and a missing final newline remain intact.

5. Boundaries, errors and existing Preview limits

This is an importer, not an editor, compiler, runner, repository importer or notebook-cell extractor. A notebook file is retained as JSON text; embedded cell languages are not extracted. Source imports are never followed. Binary files, archives and PDFs need their appropriate import modules. Imported code is never sourced into Tcl, loaded into Python or registered as a framework plugin. An explicit later system-open action belongs to the OS/framework viewer association, not this importer.

Duplicate Dataset IDs are rejected. A source failing full validation does not retain a partial payload, RAW transaction or Dataset metadata. Existing Datasets are kept. Cooperative callbacks expose progress/cancellation through the framework event loop. Uninstalling the plugin leaves previously imported data and metadata intact, though its decoded preview provider is no longer installed.

GX-TXT 0.9.8.09's shared Preview binary guard intercepts NUL-containing text (notably UTF-16/32), certain binary-looking filename suffixes and large files with no early newline. In these cases the standard GUI uses its safe metadata fallback instead of the plugin's decoded snippet. Import and language/encoding metadata still work. No CORE patch or runtime override is installed to bypass this behavior.
