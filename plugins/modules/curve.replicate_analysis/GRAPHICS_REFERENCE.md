# Replicate Curve Analysis — Public graphics integration

SPDX-License-Identifier: GPL-3.0-or-later

## Objective

`curve.replicate_analysis` must own the user-visible graph identity while using the standard GX-TXT scientific renderer and every applicable shared graphical service. No module-private scientific renderer is permitted.

## Authority matrix

| Function | Current authority |
|---|---|
| Scientific graph data | Published `curve.replicate.*` Datasets |
| Dataset/X/Y/family/filter/order | CORE Graph Series API v1 |
| Representation and explicit Series style | Series Editor Extension API v1 provider state |
| Renderer | `plot.dataset` through public Plot Dataset APIs |
| Width/height/DPI/fonts/background/default line width | Graphics Inheritance API v1 |
| X/Y ranges, units, grid, tick state | shared CORE Axes/Grid state |
| Plot margins/layout sliders | shared CORE plot layout state (`layout_*`) |
| Legend position/layout/font | common Legend state |
| Level transforms | Level Scale API v1 |
| Annotation overlay/export | Plot Annotation API v1 |
| Select Region | Plot Region Selection API v1 |
| Variants/Clone | Plot Module API v1 |
| USE/NON USE and scheduling | Graph Workflow API v1 |
| Rerender lifecycle | Graph Workflow + public Plot Dataset rerender |
| Visible PNG ownership | `curve.replicate_analysis` |
| Geometry sidecar | generated by renderer, copied beside producer PNG |

## Line-width precedence

The integration does not insert numeric style.line_width into a PlotSpec Series unless explicitly requested. The module does not declare a graph-level line-width field. The hidden backend is explicitly set to `line_width=inherit` before every render, and the provider Series extension uses a blank line width by default.

The effective precedence is therefore:

```text
Graphics line_width
  -> optional explicit Series line_width
```

## Axes and Plot layout

The module does not persist duplicate `x_min/x_max/y_min/y_max` configuration fields. The shared Axes/Grid state is authoritative.

The producer runtime contains the current `[axis.<producer-graph-id>]` section. Before requesting the backend render command, the graphics bridge copies the complete axis state to the hidden backend graph key. This includes the `layout_*` fields written by the Plot layout controls even when the separate axis override is disabled.

No layout geometry is calculated by the plugin.

## Legend

The producer `[legend.<graph-id>]` runtime state is projected to the backend graph key before rendering. The plugin does not implement legend placement or legend geometry.

## Level Scale

The producer `level_scale.<graph-id>.<axis>` runtime sections are copied to the backend graph key through Level Scale API state before rendering.

## Series

The standard Series editor owns scientific Graph Series state. The provider extension adds only presentation fields that generic Graph Series does not own:

- representation kind;
- explicit color;
- explicit line style;
- explicit line width;
- marker;
- marker size;
- marker fill;
- opacity.

Blank/inherit values are intentionally non-overriding.

A Plot Module Variant inherits base provider presentation until the exact Variant receives an explicit presentation override.

## Select Region

All four graph offerings declare:

```ini
supports_region_selection=1
region_selection=rectangle
```

The framework owns interaction, persistence and coordinate conversion. The renderer produces normal GX-TXT geometry metadata. The bridge copies the matching `.gxtxt_plotmeta/<basename>.ini` sidecar next to the producer-owned PNG, which is required by the Plot Region Selection API for accurate pixel-to-data mapping.

The plugin does not implement its own selection canvas or coordinate conversion.

## Annotations

All graphs continue to declare the standard Annotation API capability. Annotations remain framework-owned overlays and do not modify the scientific PNG.

## Variants and rerender

All graphs use:

```ini
supports_variants=1
variant_data_model=series
series_editor=standard
```

Producer Variants remain `curve.replicate_analysis` objects. Each producer graph/Variant has a stable hidden Plot Dataset backend Variant selected by a producer-owned provider key.

The backend artifact is deleted after a successful copy so it does not appear as a duplicate graph. The backend PlotSpec/cache/Variant state is retained for subsequent rerender.

Normal analysis uses the public `render` command. Producer rerender uses the public `rerender` command.

## Private-renderer regression guard

The production runtime must contain none of the following result-render calls:

```text
plot(
bar(
errorbar(
legend(
xlim(
ylim(
gxtxt_plot_new_figure(
gxtxt_print_png_atomic(
```

These calls are expected only inside the shared renderer implementation, not inside `curve.replicate_analysis`.

## Verification checklist

In a clean Session after one successful calculation:

1. Graphs shows the four artifacts under Module `curve.replicate_analysis`.
2. Changing Global/Module Graphics line width changes line graphs while Series line width is blank.
3. Setting an explicit Series line width overrides Graphics only for that Series.
4. Plot layout sliders change the rendered margins after Apply and rerender.
5. Axes/Grid changes alter range/grid/display presentation.
6. Legend placement including manual placement rerenders correctly.
7. Series editor changes Dataset/X/Y/family/filter/order and provider presentation correctly.
8. Level Scale rerenders correctly where scientifically valid.
9. Annotate/Export annotated works on the producer graph.
10. Select Region is available and converts the selected rectangle to data coordinates using the copied geometry sidecar.
11. Clone/Variants remain owned by `curve.replicate_analysis` and preserve independent presentation state.
12. USE/NON USE affects normal scheduling without disabling explicit rerender.
13. Close/reopen preserves all persistent producer state.
14. No visible duplicate `plot.dataset` backend PNG remains after render.

## Dataset access and runtime transport

Scientific input is not read by the graphics bridge or by direct filesystem access. `curve_replicate_analysis_main.m` resolves `analysis_source.<id>.dataset_id`, resolves variables from Analysis Source metadata, and streams data with `gxtxt_table_stream_open_source()` / `gxtxt_table_stream_next()`. No source CSV header or source path is opened by the module.

The graphics bridge transport uses `gxtxt_persistent_bridge_readline()` to wait for the Tcl bridge response reliably.

## Curve-family uncertainty bands

`PLOT_DATASET_API_v2` does not allow `band` on a Series that still carries `family_variable_id`. The producer must expand that family representation before rendering. The bridge performs this expansion using public Dataset APIs:

1. Read the family and optional label variables through `TABLE_STREAM_API_v3`.
2. Preserve source encounter order.
3. Create one PlotSpec Series per family member.
4. Remove `family_variable_id`, `family_label_prefix`, and the label-only secondary variable from each expanded Series.
5. Add `row_filters=[exact_equal(family_variable_id, member)]`.
6. Preserve `band.lower_variable_id`, `band.upper_variable_id`, Series style, axis, ordering and existing filters.
7. Apply any active family filter before expansion so no empty family Series are emitted.

This is equivalent to the public Graph Series family-expansion model while keeping the user's producer Graph Series unchanged in the Session.
