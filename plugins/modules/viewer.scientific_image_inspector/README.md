# Scientific Image Inspector

Standalone GX-TXT Viewer for image editing, scientific inspection and article-figure preparation, based on GX-TXT Native2D and the configured ImageMagick engine. GPL-3.0-or-later.

**User guide:** `MANUAL.md` is the complete English manual for the current plugin. Press **F1** or choose **Help → User Manual...** to read it in a standalone searchable window (Find next, F3, Ctrl+F). It includes end-to-end microscopy, scan, multi-panel figure and ROI workflows; a complete Basic preset reference; and the publication/Workspace distinction. `CHANGELOG.md` records changes between plugin releases.

**Release identity:** the installed module descriptor (`module.ini`), package descriptor (`plugin-package.ini`) and runtime API entrypoint (`api/scientific_image_inspector_api_v1.tcl`) use one synchronized plugin version, validated by `tests/documentation_version.tcl`. `Help → About` displays the API-owned version.

Install the **complete ZIP** with **Configuration → Modules → Plugin Manager → Install**, enable `viewer.scientific_image_inspector`, then open it under Viewers. The framework baseline is GX-TXT dev096; a compatible installed version with Native2D, Workspace, Metadata and Dataset File Publication APIs is required. The plugin does not modify GX-TXT CORE, existing Viewers or scientific Session files during preparation.

**Startup:** the viewer opens with an empty canvas and an unselected Dataset chooser; it never opens the first available image or a previous Workspace implicitly. An explicit Dataset choice or Workspace open is required. Help → About shows the installed plugin version.

**Workflow:** select a canonical image Dataset; work in one main canvas; switch Annotation mode on/off via the Native2D viewport icons; edit named objects with Curve Workbench-style Native2D translate/rotate/pivot gizmos and a canvas context menu; propose image corrections on a temporary right-hand preview; choose **Accept preview** or **Discard preview** (all other editing is locked during a pending preview); add and edit named text/shapes as non-destructive image overlays; optionally assemble a multipanel figure; save a named CORE Workspace; explicitly publish the currently displayed working image or figure as a **new `image.raster` Dataset**. There is no direct Save As / Export File from the Viewer. GX-TXT can export the published Dataset independently.

**Sidebar:** one narrow scrollable vertical stack, showing Editor and Figures by default. Inside Editor, **Basic Editor** offers 15 descriptive task presets with an inspectable sequence and manual adjustments; **Advanced Editor** offers the complete descriptor-driven ImageMagick operation catalog, parameters and ROI scope. These are two alternative tool views of the same image and History, never two separate raster surfaces. Visibility is applied immediately with **Configuration → Visible sidebar sections... → Apply** and saved in the **current CORE Workspace** as `sidebar_sections`; it no longer writes GX-TXT User defaults. Initial defaults are obtained from Configuration when starting a new draft. Other sidebar sections include Annotations, Image Info, Colors, History and Publish. The former separate Advanced section is now inside Editor. **Analyze → Image** explicitly selects Working / Source / Preview with separate optional Working ROI. F1 opens an independent viewer-only manual window. **Bottom strip:** CORE provides Description (current message), grouped History rows, timeline navigation, details and bounded upper context menus. Clicking an older step inspects it read-only; returning to Latest restores normal editing. A confirmed Restart here truncates later editing checkpoints in the Workspace; source Dataset files are never altered.

**Pointer and error handling:** The Native2D viewport toolbar uses viewer-owned, context-aware tool callbacks; its tooltip windows follow the Viewer's own window. Description / History opens as a compact upward popup to stay on-screen near the bottom. Invalid or zero-length drawing gestures are rejected before the Workspace/History changes and reported in the status strip. Old invalid annotations are isolated on redraw, with their names/IDs and coordinates shown in diagnostic stderr and status, without altering saved objects. The timeline context menu and drawing-tool activation are guarded against leaving the Viewer in an invalid editing state. Rejected edits do not publish image data.

**Processing:** 69 ImageMagick catalog entries: 46 implemented operations with typed validation, 17 recognized but not enabled and 6 intentionally disabled. Source-backed zoom LOD uses ImageMagick while geometry, canvas transforms and pointer interaction reuse the Native2D public host. Editing creates an ordered recipe; no source image is overwritten.

**Figures:** up to 12 canonical parent image panels; editable panel settings, directly selectable named annotation shapes/text and independent per-image/figure annotation layers. GUI previews remain disposable; exact full-resolution output is processed at publication. Image output formats are PNG16, TIFF16 and TIFF32f (subject to actual ImageMagick support). Scientific limitations are described in `MANUAL.md`.

**Public manifest API:** results contain a validated processing manifest stored by CORE Dataset Metadata, including lineage, SHA-256s, operations, ROIs, annotations, layout, output characteristics and ImageMagick version. After activating `SCIENTIFIC_IMAGE_INSPECTOR_API_v1`, modules may call `::GX::SII::manifestGet dataset_id`, `::GX::SII::manifestSummary dataset_id`, or `::GX::SII::apiCall manifest_get dataset_id` and `::GX::SII::apiCall annotations_json dataset_id`. Full contract: `docs/API.md`.

**Files:** `api/` contains activation and Workspace provider descriptors. `runtime/catalog.tcl` defines catalog entries; `runtime/engine.tcl` processes images and publishes; `runtime/manifest.tcl` defines the queryable metadata contract; `runtime/annotations_json.tcl` emits a JSON overlay view of retained annotations; `runtime/article.tcl` composes figures; `runtime/native_canvas.tcl` uses public Native2D geometry and canvas transforms; `runtime/annotation_tools.tcl` owns the Native2D pivot/transform controller and context actions; `runtime/editor_controls.tcl` owns selector modes, the annotation clipboard, Edit actions and semantic Viewer Settings; `runtime/roi_context.tcl` owns the context-sensitive ROI/figure menus and generic validated ROI operation parameter editor; `runtime/lod.tcl` performs bounded background LOD; `runtime/history_strip.tcl` supplies scientific capture/restore hooks and independent image/figure domain adapters to CORE native History, shared controls and asynchronous persistence; `runtime/gui.tcl` and `runtime/article_gui.tcl` implement GUI and editor state. `tests/` covers isolated processing, annotation, publication and Tk/Native2D workflows.

**Tests on Debian:** `GXTXT_TEST_MAGICK=/path/to/magick GXTXT_TEST_CORE_DIR=/path/to/readonly-GX-TXT/core bash tests/run_tests.sh`. Tests use disposable images, Session API doubles and Xvfb where available. Real Plugin Manager install and Session persistence in an accepted dev096 instance are not claimed as tested.

**Viewport annotation editing:** a shared Native2D toolbar has Select, Transform, Pan, drawing and Zoom icons. The drawing menu includes **Add Text**, Arrow, Line, Rectangle and Ellipse; select Add Text, drag a text box directly over the image and type into it. Its attached mini-toolbar uses the framework color chooser and verified ImageMagick fonts, with size in px/pt. Right-click the canvas for the same creation and object actions. Right-click a selected object for Rename, Edit Text, Translate, Rotate, Pivot, Style or Delete. Native2D retained selection geometry, gizmo rendering and drag transactions manage movement/rotation; Tk is the text-glyph/editor presenter. Names, stable IDs and transformations survive Workspaces and the JSON manifest. Esc exits annotation editing; the Select icon activates object selection, with Object/Window/Polygon/ROI choices on right-click. Objects stay visible. Numeric coordinates remain hidden unless enabled in GX-TXT Configuration.

## Editing controls

The Annotations sidebar is optional and is never auto-opened when entering annotation editing. Right-click the Native2D Select icon for Object, Window, Polygon and Image ROI modes. The Edit menu exposes Select All/None, annotation Copy/Paste and Undo/Redo. Configuration keeps Visible sidebar sections directly accessible and groups the remaining controls under Viewer settings (Interface, Annotations and Processing). Multiple selection supports Copy/Paste; Native2D transforms still target one active annotation at a time. Read MANUAL.md for details.

## Current context-sensitive editing

- **Operations** is no longer a top-level menu; the Advanced Editor already contains the catalog.
- **Sidebar visibility** uses immediate **Apply** and persists through GX-TXT `SESSION_WORKSPACE_API_v1` in each Workspace, not User defaults. Other Workspaces are unaffected. Changes applied before any image is opened remain in the draft until a Workspace exists.
- **Right-click inside the image ROI** opens crop, working-image statistics/histogram, cursor pixel inspection, compatible task presets, catalog-backed ROI operations grouped by family, Advanced Editor (ROI), and Clear ROI. Each operation is subject to installed ImageMagick support; those requiring parameters use one generic validated dialog, and any processing starts an unaccepted preview. Operations that alter image geometry are intentionally excluded from ROI-only processing.
- **Composed figure mode:** right-click offers **Edit source image**. A requested image filter offers a guided switch to the source image rather than only displaying an error. Figure panels and independent annotations remain in the Workspace. Older alpha Workspaces without a saved `canvas_mode` default to image mode; backward-compatible automatic figure inference is intentionally not implemented.
- **Future architecture:** independent image layers and figure composition are not remodeled now. Further integration will be evaluated after corresponding Native2D CORE interfaces exist.

**DEV111-P017 History:** Accepted gestures update CORE RAM state and ordered background journals; only explicit Save/Close/source or Workspace changes project complete records into the canonical Document. Image and figure Undo remain separate scientific domains inside the same CORE service. The former private 80-state timeline and figure Undo stacks are removed. Complete bounded records use the compatible optional `scientific_history` / `domain_history` payload fields; older `history_timeline` values are imported without silently dropping intermediate states. Acceptance and durable persistence are reported separately.
