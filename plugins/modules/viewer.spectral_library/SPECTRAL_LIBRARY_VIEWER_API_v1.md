# Scientific Spectral Library Viewer API v1

The module's public `SPECTRAL_LIBRARY_VIEWER_API_v1` entrypoint registers backend `spectral_library_tk` through `::GX::viewerBackendRegister`. GX-TXT activates it lazily when `::GX::viewerOpen viewer.spectral_library spectral_library` is invoked. Provider discovery is headless. The callback receives the standard Viewer action and resolved scene. The Viewer reads spectra only through CORE `::GX::ReferenceLibraryAPIv1`, Session spectra through Dataset Access, and durable Session presentation state through Interactive Document API v1. It does not implement a second matching algorithm. Reference browsing is independent of Session Inspection; optional Session spectrum and ranking selectors are empty when there is no compatible Session data.

Managed IR libraries are discovered through `SCIENTIFIC_LIBRARY_MANAGER_API_v1`, and the toolbar provides **Install library...**. With no compatible library, the status line explains the missing capability. The install action selects a data-only ZIP and calls the public manager; it then refreshes the library list and reference spectra. Existing user-authored libraries remain visible. Library update and removal are generic manager operations and require no viewer installer code.

Version 1.0.9 adds a visible **Update / remove reference...** action. The maintenance dialog shows source ownership and content hash, requires a new library ID/version, and calls only the versioned CORE `forkLibraryVersion`, `updateReference`, and `removeUserReference` methods. Updating may change metadata alone or use a selected CSV/JCAMP replacement, with the spectral kind and ordinate checked before publication. Removal is enabled only for a user-owned source. The original library remains available; analysis Sessions retain their recorded library ID/version/hash until explicitly reconfigured. Review a new version before choosing it for future analyses.

## Viewer Provider callback

`::GX::SpectralLibraryViewer::viewerDispatch {action scene}` is the trusted Tcl Viewer Provider callback. `action` is `open` or `rerender`; unsupported actions raise an error. `scene` is the resolved Viewer scene dictionary; its optional `open_context` dictionary is forwarded to the existing `_open` owner for the documented library/reference/Session selectors. Both a new and a reused Viewer return a dictionary with `status opened` and `window` containing its actual Tk path. This activation result is not a spectral-match result. ReferenceLibrary, ScientificLibraryManager and canonical Dataset/Document services retain spectra, provenance and optional Session matching; the callback grants no Script Bridge or C++ SDK operation.
