Problema affrontato

Nella dev-108 originale, ripetere un comando dello stesso Viewer C++ può causare nuove compilazioni di viewer.so anche con il progetto invariato.

Comportamento previsto

  • Confronta hash del sorgente, design, progetto, SDK, compilatore, adattatore, policy e backend, più ricevuta e binario effettivo, prima di riutilizzare il Viewer compilato per lo stesso progetto.
  • Solo all’avvio di una compilazione Clang reale per l’evento appare una piccola finestra Tk non modale: Compilazione C++ del viewer in corso...; si chiude a fine evento, errore o chiusura del Viewer.
  • Dopo l’esito positivo la barra di stato indica COMPLETED (C++ compiled) oppure COMPLETED (C++ binary reused). Non richiede terminale né log di fallback e non altera stdout/stderr dei Script Job.
  • Build/Export espliciti e debugger seguono i percorsi precedenti. Un nuovo progetto temporaneo può legittimamente compilare al primo utilizzo.

Installazione sulla dev-108 originale

Chiudere GX-TXT. Se è stata applicata la v2, eseguirne prima il rollback usando il backup originale verificato; non sovrapporre le patch. Estrarre lo ZIP v3 fuori dal framework ed eseguire dalla cartella estratta i comandi seguenti sulla dev-108 originale:

ROOT="$HOME/gxtxt/gxtxt_pipeline_v09810dev_108"
python3 backport.py --check "$ROOT"
python3 -m unittest -v test_patch
python3 backport.py --apply "$ROOT"

Verifica dopo il riavvio

Riavviare GX-TXT e ripetere la stessa azione nel medesimo progetto Viewer C++ invariato. La prima compilazione può mostrare un popup breve; i successivi riutilizzi non dovrebbero mostrarlo. La barra di stato conferma se ha compilato o riutilizzato.

Ripristino della dev-108 originale

Utilizzare il comando ROLLBACK stampato dall’installatore v3. Ripristina entrambi i file dai backup verificati e rifiuta di sovrascrivere successive modifiche locali.

Compatibilità e limitazioni

  • Esclusivamente per la dev-108 originale, commit 6371001a219a4e611ce89c8b396c62294e6b979c: verifica i file Python E Tcl. La dev-109 e tutte le altre versioni sono incompatibili per definizione.
  • Hotfix.2 sostituisce hotfix.1, ma non può essere installata sopra la v2. Ripristinare prima i file originali con il rollback verificato della v2 oppure reinstallare una dev-108 pulita; non forzare la sovrascrittura.
  • Le ricevute e i binari in cache locali al progetto non sono una garanzia contro manomissioni intenzionali: usare soltanto progetti Viewer attendibili.
