# Internal CORE HTML host draft

TASK210 developer implementation; not installed or graphically accepted. The existing-owner host extension is implemented separately in the same batch, capability-gated on the managed request owner and prebuilt identity. Existing HTML `render source`, document parser library, XML/Markdown/code owners and default Makefile target retain their existing contracts. MAIN accepted the existing-owner HTML extension on2026-10-22; this batch is its internal backend, with caller wiring and graphical acceptance still separate.

The optional `make html-runtime HTML_QT_SDK=PRIVATE_OVERLAY_USR HTML_BUILD_DIR=RAID_SCRATCH` target compiles `html_runtime.cpp` as one prebuilt C++17 executable using matched Qt6 WebEngine headers, Qt6 Widgets/Network metadata and matching shared runtime libraries. Build output must stay on RAID. Normal runtime never compiles or links. This initial implementation supports the Debian X11 Qt `xcb` platform only; Windows/Wayland are unverified. The private development overlay records every header/runtime link and leaves original package bytes/system dependencies unchanged.

## Internal pipe protocol

Launch by trusted CORE owner only: `gxtxt_html_runtime --parent-window XID ?--tcl?`. The host wraps that authorized parent with Qt `QWindow::fromWinId`, embeds its WebEngine view and runs its own event loop. No standalone-window fallback. The future CORE adapter must verify ownership/widget generation before launching; a bare numeric XID is not authorization. The executable is not exposed to authored Viewer source or page JS.

Stdin carries bounded newline-delimited JSON objects. Default stdout is JSON; the trusted Tcl owner uses `--tcl`, which encodes flat receipt dictionaries with the existing Tcl list encoder and `GXHTML1 ` prefix. No Tcl interpreter is created/evaluated. Stderr is separate diagnostics. Maximum control frame16KiB, bounded output queue64KiB. No Tcl, shell, JavaScript evaluator, raw browser channel, Script Bridge or scientific publication operation. Commands use exact field sets and bounded scalar types:

| op | Remaining required keys |
| --- | --- |
| load | request_id, generation positive increasing integer, root canonical absolute admitted asset directory, relative package HTML path, sha256 lowercase64hex, source_id bounded owner ID, media `offline` or experimental `youtube` |
| resize | request_id, width/height integer1..16384 |
| visible | request_id, value boolean |
| zoom | request_id, percent integer50..300 in25 increments |
| relative | request_id, target relative package path/anchor, no query or scheme |
| find | request_id, text (may be empty, at most1024 UTF-8 bytes, no NUL) |
| back/forward/home/reload/stop/inspect/close/focus | request_id only |

Every request identity is1..64 safe ASCII characters. Load source IDs are1..256 safe ASCII identity characters. The trusted caller owns canonical Dataset/descriptor resolution and Session/source admission. Browser receives only admitted root/relative file and source digest; there is no Dataset registry or scientific reader in this process. Future caller must invalidate the native surface on Session/source change and correlate generation/request receipts. The existing HTML façade now performs those owner checks; actual embedding and lifecycle acceptance remain separate.

Receipts use `schema=gxtxt.html_runtime.v1`, event/state/generation/navigation_sequence/navigation_pending/request_id/source_id/source_sha256/can_back/can_forward/zoom_percent; relative_url is a scoped presentation location, while source_sha256 retains the bound source identity, with optional code and outward URL. Actual OS paths, parent XIDs and process IDs are not echoed to page/public receipt. A source load first reads bounded actual bytes and verifies the trusted digest; invalid source leaves prior binding unchanged. Accepted new load gets a fresh128-bit origin nonce and replaces resource scope. Delayed load notifications from an old origin are ignored. One same-source navigation is allowed in flight; commands receive NAVIGATION_BUSY until its terminal event drains, including after Stop. Every accepted navigation arms its start deadline before Qt is invoked. A stop before start retires the host immediately; a started Stop or timeout either drains its terminal or retires the host within500ms. Same-document/no-op navigation does not wait for a start event that may never occur. A source-generation/navigation sequence, exact expected URL and observed-start requirement gate terminals; load/inspection request IDs stay separate. Source-only reducer checks cover these guards, but Qt event ordering, same-document anchors and real Back/Forward/Stop require the MAIN GUI slot before acceptance. Source bytes are checked again when served to the renderer.

`--probe`, `--probe-tcl`, `--check-control`, `--check-navigation` and `--check-source ROOT RELATIVE SHA256` are QCoreApplication-only developer diagnostics: no GUI/X11/Chromium creation. They exercise the same production command parser/asset reader. Probe reports actual loaded Qt version and explicitly `rendering_verified=false`; it is not a browser availability test. Check-control accepts JSON lines and returns accepted operation or bounded error code. Check-source reads and fingerprints only the admitted bounded ordinary file. `--probe-tcl` fingerprints the actual executable and writes the build receipt used by the host; the optional Makefile creates this `.info` beside its scratch binary. These modes are not public HTML APIs.

## Boundaries implemented

A native custom scheme serves only current nonce/root resources. Path components reject absolute paths, traversal, repeated/ambiguous encoded paths, backslashes and NUL; root canonicality and directory/file reads use Linux `openat` with `O_NOFOLLOW`, regular-file/type/size checks and change detection. HTML source limit4MiB; each other asset16MiB, unique package asset budget64MiB/4096 resources. Source/root symlinks, FIFO/device/directory sources are refused. The scheme additionally admits only HTML/CSS/JS/JSON/text/image/font/media web-asset extensions and rejects hidden paths; it cannot serve module Tcl/Python/native implementation files. Retired-origin asset failures are suppressed instead of emitted under a successor source. Source directory rename cannot redirect the retained directory FD to another directory. These are presentation budgets, not new canonical scientific limits.

Off-the-record profile, memory cache, no persistent cookies/local storage; JavaScript DOM/CSS/SVG/canvas remain enabled. File URLs/general network/workers/WebSockets/unknown schemes are denied. File chooser, downloads, popups, page modal dialogs, clipboard JS grants, camera/microphone/screen/location/notification permissions and certificate bypass are denied. No QWebChannel or page-to-command bridge exists. Chromium sandbox remains enabled; root execution, sandbox override/Chromium flag or remote-debugging environment is refused. Linux parent-death signal and control-pipe EOF end the owner. Foreign-parent embedding, child-renderer drain and sandbox effectiveness still require actual coordinated GUI/process checks.

The experimental `youtube` profile only admits HTTPS GET subresources/frames on declared YouTube/player/CDN families, never remote main-frame navigation or arbitrary host-supplied network policy. Remote origins cannot request the scoped local scheme. It emits `YOUTUBE_PLAYBACK_UNVERIFIED`: legitimate YouTube Referer/client identity and real codec/service playback are still open review/GUI work. No fabricated client identity/header or playback claim. This profile is a bounded initial transport implementation, not completion of TASK210 YouTube functionality.

Intentional outward HTTP(S) link requests emit `external_link_requested` only after a recent one-use native input event scoped to this view/source generation/navigation sequence and main-frame link navigation; no external process/browser is opened here. The existing façade validates current source identity and uses the existing safe opener. Input grants reset on source/navigation change, hide, timeout, renderer termination and close; actual intentional-click semantics remain a GUI gate. Generator URI/catalog dispatch is intentionally not adopted while its exact public owner review is pending. User gesture, focus/tab traversal, CSS/DOM, media, resizing/mapping, source switches and parent destruction are all GUI acceptance work routed through MAIN; pure parser/asset tests cannot establish those behaviors.
