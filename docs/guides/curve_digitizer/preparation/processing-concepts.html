Use enhanced pixels with the original source in view

Enhancement can make a faint curve easier to inspect. Preserve the original image, the processing recipe and the distinction between a visible preview and a published scientific result.

Different appearances can share one coordinate system

The documented processing pipeline preserves raster dimensions and geometry. A displayed processed pixel corresponds to the same original-raster position. Changing contrast or choosing a channel does not redefine the calibration, rewrite original click coordinates or change the original image's byte identity.

This coordinate relationship does not guarantee that enhancement preserves a feature's apparent boundary. Thresholding, sharpening or local contrast can change which pixels look like an edge or curve. Inspect the original before committing a scientific interpretation.

The derived stream starts from the viewer's decoded RGB image and produces RGB PNG. It is not a byte-for-byte preservation of higher-bit-depth acquisition channels. Keep the original canonical acquisition for quantitative image metrology and retain any source-specific channel interpretation.

The deposited viewer provides no crop, resize, rotation, flip or perspective correction in this processing pipeline. Geometry-changing transformations need an appropriate separate tool and explicit provenance; this explanation does not imply that an old calibration remains valid after such a transformation.

The recipe includes order, enablement and exact values

A reproducible processing recipe describes the enabled operations, their parameters and their order. A disabled filter does not participate even if its remembered numeric value remains visible. Preserve enablement along with values when explaining an example.

The documented operations include channel selection, grayscale, median denoising, auto levels, contrast stretch, brightness/contrast, gamma, local contrast, sharpening, inversion and thresholding. Each changes different aspects of appearance; none establishes that the desired scientific curve has been identified.

Changing operation order can change the result. An explicit switch from Advanced to Standard applies the standard ordering; it is a meaningful processing change. Do not silently present a reordered pipeline as the same recipe.

The automatic suggestion deliberately avoids thresholding, heavy median denoising, inversion and geometric resampling/cropping in the deposited implementation. It does not guarantee better tracing or greater scientific accuracy. Its restore action returns the preceding recipe while working on the same source and configuration; final tutorials must demonstrate the actual accepted version's behavior.

The documented live preview debounces slider updates and discards obsolete results. A manual preview action is also available. Record a current preview before comparing outputs: an old visible image does not prove that the latest settings were processed. These are source descriptions, not a measured responsiveness or performance acceptance.

Inspect appearance without silently changing points

The deposited split comparison places the original on the left and the processed image on the right. Each side has its own viewport; an optional synchronization aligns pan and zoom around the same original-raster coordinate. Different panel widths can still display equal zoom with the same center.

For a meaningful visual comparison, inspect the same source region at a useful common scale. Fit-to-panel can show different apparent image sizes when the viewports differ. A larger-looking feature in one panel is not evidence that the raster geometry changed.

Read-only point overlays help relate existing digitized points to both appearances. The documented comparison does not add, move or delete curve points. Curve editing belongs to the active Curves context; Calibration retains its explicit calibration actions. A view change or filter adjustment must not be described as a scientific point edit.

A processed image can support tracing while the original raster coordinate mapping stays authoritative. Select the intended trace input deliberately and review crossings, faint segments and affected edges against the original. See the tracing explanation for the distinction between a proposal and accepted scientific points.

An enhanced image and a digitized curve are separate outputs

Previewing a recipe does not create a canonical output Dataset. Under the documented workflow, image publication deliberately creates a new standalone image.raster Dataset with a stable output ID. The original Dataset is retained. An optional human-readable description belongs to notes; it does not replace the stable identity.

A separately published processed image carries its parent identity and processing lineage. Opening it as a source in a new digitizer configuration creates a new source context. Its own bytes and identity must be recorded; visual similarity to the original does not make it the original acquisition.

The documented processed-image lineage includes the parent Dataset and SHA-256, exact ordered operations and validated parameters, runtime version, dimensions, an identity pixel transform and a deterministic processing fingerprint. CORE supplies the output-byte identity and publication transaction. Consumers should use the existing public processed-image API rather than reverse-engineering private stored fields.

Diagnose missing processing without changing the acquisition

The deposited module obtains ImageMagick through the framework Runtime configuration. With that runtime absent, processing and processed-image publication are unavailable; the viewer's other documented functions remain usable. A missing runtime is a configuration dependency, not a reason to alter the vendor module or silently claim a processed result exists.

After an error or stale preview, retain the source and desired recipe, then confirm the runtime and current preview through the normal framework workflow. Do not compensate for a runtime error by changing calibration or scientific points. Publication identity and per-output failure recovery are explained in the publication chapter.

Brightness, apparent sharpness, overlay visibility and display opacity do not establish measurement precision. Preserve explicit quality observations and justified uncertainty declarations independently. Read uncertainty interpretation before assigning a statistical meaning to an enhanced curve.

The final tutorials will show the actual original/processed inspection, ordered recipe, separately published image and curve identities, source lineage and canonical Dataset Preview. No such installed workflow has been verified by this preparation chapter.
