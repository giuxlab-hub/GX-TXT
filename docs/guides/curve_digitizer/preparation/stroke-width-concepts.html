Describe ink width without inventing measurement precision

The stroke-width diagnostic describes the thickness of a curve in its original raster. It is separate from the region searched by tracing and from a justified uncertainty model for a scientific point.

Keep the measured quantity separate from the setting

Sharing a unit does not make these values interchangeable. Changing a search setting changes a procedure. Measuring ink geometry produces a diagnostic. Declaring a statistical model assigns a further scientific interpretation that needs evidence and the supported CORE owner.

Inspect which automatic probes support the result

The 2.0.9 manual places an optional Stroke width editor with the curve controls. The panel is collapsed initially; measurement is off by default and is enabled separately for each curve. The documented automatic method requires at least three accepted scientific points and samples the original raster along normals to their accepted sequence.

It estimates half-contrast full width from suitable cross-sections and reports a median, range, interquartile range and accepted/rejected probe counts. These are descriptive summaries of the accepted probes. Low contrast, overlapping lines, edges and multiple nearby strokes can cause rejection.

Review both the width summary and probe coverage. A median from a few suitable locations does not establish uniform width over an entire curve; rejection may omit exactly the difficult regions of interest. An unavailable result must remain unavailable. It is not a measured zero-width line.

A changed accepted point sequence can affect where normals and probes are evaluated. Retain the source and trace identities reported by the supported owner, and inspect the actual current status before reusing a measurement. The final tutorial must show genuine results and failed/unavailable cases honestly; a synthetic value in explanatory prose would not substitute.

Choose corresponding visible boundaries

The documented manual method uses two source-bound boundary paths, with at least two handles on each. Their square cyan/lime handles are distinct from orange tracing guides and red exclusion nodes. Boundary editing and measurement should be explained as their own operation, without conflating a boundary handle with an accepted curve point.

Choose the same part of the stroke on both sides, with matching extent and traversal direction. The diagnostic estimates separation between corresponding positions along the two interpolated boundaries. Different spans, reversed correspondence, crossings, neighboring strokes or ambiguous edges can make a numerical separation uninformative.

Smooth boundary interpolation does not establish where a physical signal lay before printing, scanning or rasterization. A tidy pair of splines can still describe the wrong ink edges. Inspect the original pixels and retain limitations of boundary selection.

The source manual documents reversible delete/clear/reset operations through Edit Undo/Redo. Preserve the selected curve and source context when describing those actions. Actual keyboard/mouse behavior, status updates and recovery must be demonstrated in the allocated real GUI after the release handoff.

The selected curve owns its settings and geometry

Version 2.0.9 specifically documents selection synchronization: selecting a different curve updates its measurement enablement, method, probe radius, result status and Calibration summary. A previous curve's controls must not be treated as the new selection's state. The panel remains collapsed when opening a new configuration while saved values remain per curve.

Use immutable curve identity for grouping and interpretation. A display name can change and does not establish that two records belong to the same curve. Likewise, identical filenames or visually similar rasters do not prove the same source bytes.

Keep stale or unavailable diagnostics explicit when the source or relevant trace changes. The public documentation distinguishes configuration reads in the active Session from published Dataset reads. A record's existence is not evidence that its source and geometry are current; final content must follow the actual owner status and supplied integrity qualification.

A published width report is a diagnostic snapshot

The existing public contract CURVE_DIGITIZER_STROKE_WIDTH_API_v1 provides configuration/curve reads and published Dataset reads through the established CORE services. It does not require a private scientific consumer to inspect the viewer's mutable GUI or parse a private configuration file.

The documented published report groups records by curve identity and retains source identity, method, pixel units, state and available width/probe summaries. It is a publication-time snapshot. Editing a current configuration does not silently update an already published Dataset.

The public contract explicitly declares no automatic uncertainty propagation. Ink width does not populate pixel sigma, create Numeric covariance, or authorize GLS/ODR weights. Connecting width to centerline localization would require a separately justified error distribution and an appropriate supported scientific model. Repeated digitizations of the same raster are also not independent physical measurements of the original specimen or device.

Preserve these separate questions when interpreting a result:

  1. Which source bytes, curve and accepted trace does the diagnostic describe?
  2. Which method and probe/boundary coverage support the reported width?
  3. Is the record current, unavailable, inactive, stale or a publication-time snapshot?
  4. What independent evidence, if any, supports a separate scientific uncertainty declaration?
  5. Which real public CORE scientific contract admits the intended downstream use?
