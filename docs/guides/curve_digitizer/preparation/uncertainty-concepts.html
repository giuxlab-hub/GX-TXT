Keep uncertainty tied to its evidence

An uncertainty declaration describes a stated measurement model. Its meaning comes from the source, assumptions, units and correlations retained with the scientific result.

This chapter follows deposited dev109 documentation. Final controls, limits and supported consumers must be checked against the actual unchanged vendor version accepted in dev110. Record what supports the model

Preserve the actual source identity, original points, calibration identity and rationale for each declared input. Raster resolution, snapping, apparent line width, a visual quality score and repeated clicks can inform an investigation. None of them automatically supplies a statistical error model.

An empty field, an explicit justified zero and an unknown uncertainty convey different information. The documented editor supplies no automatic numerical starting values. A declared zero localization contribution does not erase a nonzero calibration contribution or guarantee that a particular fitting method is admissible.

A full interval width is different from a standard uncertainty

For a uniform distribution over a declared full interval width w, the standard uncertainty is w/√12. The half-width is w/2. Confusing these three quantities changes the scientific interpretation.

These declarations use the same entered numeral and produce different standard uncertainties. Neither is a recommendation for a default pixel error. Under a fixed illustrative linear scale of 0.1 V per pixel, the first declaration alone gives approximately 0.0577350 V standard uncertainty, while the second gives 0.2 V. Any uncertain calibration would need its additional declared contribution.

A scientific X uncertainty has X units; a scientific Y uncertainty has Y units. Their within-point covariance has the product unit X×Y. A unit label does not itself establish a valid conversion: follow the public CORE unit interpretation, particularly for compound or custom symbols.

One calibration can correlate many points

Point-local contributions and shared calibration contributions have different effects. A common uncertain axis limit or reference position can move several scientific points together. The standard uncertainty attached to each row cannot, by itself, tell you how those rows co-vary.

Illustrative model: let two scalar errors be e₁ = l₁ + c and e₂ = l₂ + c. Assume the two local terms are independent of each other and of the common term, with local standard uncertainties 0.3 V and common standard uncertainty 0.4 V. Both marginal variances are then 0.3² + 0.4² = 0.25 V², so each marginal standard uncertainty is 0.5 V. Their covariance is 0.4² = 0.16 V².

For the average of those two values, the standard uncertainty is √[(0.25 + 0.25 + 2×0.16)/4] ≈ 0.452769 V. Treating the marginals as independent would instead give approximately 0.353553 V. The common contribution remains when the local contributions are averaged. These results follow this explicitly simplified model; they do not estimate uncertainty for a real digitized curve.

The documented product retains point-local and calibration-shared factors, as well as marginal values. Its within-point X/Y covariance is distinct from cross-point covariance induced by shared calibration. Preserve the full supported scientific interpretation when selecting a downstream fitting route.

Review the actual scientific inputs before publication

A saved declaration belongs to specific scientific inputs. Under the documented behavior, changes to the source, calibration or scientific points invalidate its review and require explicit review again before uncertainty-enabled publication. Notes and visual opacity are not changes to those scientific inputs.

The dev109 documentation describes one calibrated realization per uncertainty-enabled output Dataset. Separate outputs evaluate the declaration for their respective accepted mappings. A combined output with multiple realizations and enabled uncertainty is rejected because it needs a further model for shared original pixel errors across realizations. Ordinary combined output without an uncertainty declaration is a separate supported case.

Publishing calibrations separately does not establish statistical independence between the resulting Datasets. They can still share a source, original clicks or calibration information. Do not assume that the documented per-Dataset factor representation supplies a validated cross-Dataset correlation model.

A physical scale bar needs an appropriate physical measurement model. Generic homography-corner perturbations do not describe the bar's declared physical-length error or its center/inner/outer tick convention. The documented implementation rejects nonzero corner uncertainties for this scale-bar case and directs the operator to a justified physical override until a dedicated model exists. Read the scale-reference explanation alongside the actual source producer's convention.

The deposited documentation bounds uncertainty-enabled output to 4096 rows per Dataset, compressed factor metadata to 1 MiB, and full covariance materialization to 512 original rows. Compact retained factors and a materialized full matrix are different representations. These are dev109 source limits awaiting actual dev110 confirmation, rather than new limits defined by this manuscript.

Let the public scientific owners qualify the fit

The documented uncertainty publication depends on CORE Numeric and Statistical Semantics. Missing services or a mismatch between complete factor arrays and the authoritative numerical result must be reported through the CORE owner. Preserve the unchanged vendor module; an illustrative formula in this guide is not a private substitute for the installed numerical service.

For an eligible response-only generalized least-squares route, the public workflow requires the managed full response covariance in original scientific row order. That qualification excludes predictor uncertainty. A diagonal weighting scheme cannot silently replace shared calibration covariance, and within-point X/Y correlation can affect whether a diagonal orthogonal-distance route is eligible.

Inspect the actual public scientific report, source/point/calibration identities, units and fit qualification. Preserve any unsupported case or outstanding installed-host test explicitly. The deposited documentation still calls out the separate CORE zero-input correction and an outstanding installed-host Fitter GLS/ODR test; GUIDE has not verified those runtime dependencies.
