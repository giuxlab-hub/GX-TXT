Read a published result through its public owners

Scientific consumers use the actual Dataset identity, semantic roles and retained public provenance. They do not need the viewer's mutable GUI or a private configuration-file parser to interpret a published result.

Contract map

These are existing public contracts declared by unchanged vendor 2.0.9, not new APIs introduced by this guide. The host Tcl entrypoints below are not page JavaScript and must not be advertised as automatically available in every Script Bridge or restricted SDK context.

A documented read-only Tcl host pattern

In an already authorized GX-TXT host context, substitute the exact actual published Dataset ID before using the documented readers:

# This is a source example, not an executed tutorial result.
set datasetId {your.actual.published.dataset}
::GX::modulePublicApiActivate viewer.curve_digitizer CURVE_DIGITIZER_CALIBRATION_API_v1
::GX::modulePublicApiActivate viewer.curve_digitizer CURVE_DIGITIZER_DATASET_SCHEMA_API_v1
::GX::modulePublicApiActivate viewer.curve_digitizer CURVE_DIGITIZER_QUALITY_API_v2
set calibration [::GX::CurveDigitizerCalibration::read $datasetId]
set schema [::GX::CurveDigitizerDataset::read $datasetId]
set pixelRows [::GX::CurveDigitizerDataset::rasterPoints $datasetId]
set quality [::GX::CurveDigitizerQuality::read $datasetId]

The one-argument rasterPoints example reads at most the first 10000 original Dataset rows. Full traversal uses explicit start/count (count 1…100000) and advances by returned consumed_rows, not the length of filtered points. Curve/calibration filters are applied after each original-row batch read. Preserve original row order and the reader’s actual end condition.

Missing reports, incompatible schemas or unavailable owners must retain their actual error. Do not replace a refusal with an empty success or a manually constructed scientific record. Python/Octave callers must use only operations actually registered in their admitted Script Bridge context; this page grants no process, filesystem or scientific publication authority.

Preserve scientific rows and source roles

  • Keep the canonical Dataset identity and exact row order with the actual variable IDs, declared types, units and semantic roles.
  • Group scientific-space rows by both curve and calibration when multiple realizations exist.
  • Original raster point identity can repeat across calibrated realizations. A display overlay can deduplicate the same original curve/point without deleting scientific rows.
  • A readable curve/configuration label, a measurement ID and a transform fingerprint have different meanings.
  • Processed-image lineage requires the existing public identity/geometry owner; timestamps or filenames are insufficient.

The separate CORE Preview source receipt is a time-bound host observation, not another vendor Quality field. Retain its owner/method/status/reason and observation epoch. A cached representation must not become a claim of continuous verification.

Keep uncertainty and consumer qualification explicit

Quality and stroke-width diagnostics do not establish metrological accuracy. An enabled uncertainty declaration requires evidence and source/point/calibration binding. CORE Numeric and Statistical Semantics remain authoritative; the unchanged vendor package must not acquire a private epsilon or fallback solver.

Marginal X/Y uncertainties, within-point covariance and shared cross-point calibration terms are different information. Qualified response-only GLS requires the supported managed full response covariance and excludes predictor uncertainty. Other fit routes retain their actual eligibility rules. A zero contribution can be deliberately valid while making a specific fitting method inapplicable.

Documented uncertainty bounds include 4096 output rows, 1 MiB compressed factors and 512 original rows for full covariance materialization. Keep unsupported combined multi-calibration or physical scale-bar measurement models explicit. No example here establishes an installed Fitter run.
