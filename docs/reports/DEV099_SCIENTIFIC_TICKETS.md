## Changes and owners

- `core/tcl/single_analysis_module_api_v1.tcl`, the existing queue builder/lifecycle in `core/tcl/module_api_v1.tcl`, and `app/analysis_controller.tcl`: typed per-invocation source/config/table/binding overrides, restored before execution; registered Viewer and dependency admission; explicit BUSY; status/cancel/terminal receipts; Session/document generation/revision and exact payload+scientific-schema guards. Only the requested module is prepared; global Run selection and saved configuration remain intact. Owned process groups terminate the Standard runner and its Octave descendants together. At EOF, the existing process owner collects the true exit status instead of losing CHILDSTATUS from a nonblocking pipe.
- `core/script_bindings/public_core_services.py`: safe `analysis_capabilities` discovery. Submission/status/cancel are host-only because they address the running application's queue; detached scripts use the durable Script Job authority.
- `math.signal` provider contract files, Tcl adapter, Script Bridge and Octave validator: **the same provider-owned field and conditional TSV data drive discovery and execution admission**. Tcl contains no second filter-design rules table. Literal option defaults are applied from the shared fields; source-dependent expressions stay with the existing numerical routine. Numerical calculations and public result identities remain unchanged. Pure preflight routes through the already registered `gxtxt_signal_v1` provider entry; no global binary-function allowlist bypass is added.
- The provider-generated English form reuses `UI_FIELD_API_v1`. It hides unused operands, updates band/domain guidance, and uses the same validator for required ripple/seed, real cutoff cardinality/range and FIR parity. The entire affected Signal manual was reviewed and rewritten where it contained release-history prose; scientific content and API identities are retained. `CHANGELOG.md` retains history.

Exact before/after source digests are in `scientific-source-ledger.json`; authority/catalog fragments are `validation/official_dev099/AUTHORITY_scientific.yaml` and `CATALOG_scientific.md`. The coordinator owns the shared loader hook, final full-framework manifest, package metadata and deposition.
