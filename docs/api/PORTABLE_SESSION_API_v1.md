# GX-TXT Portable Session API v1

License: GPL-3.0-or-later

## Purpose

Portable Session API v1 exports an existing GX-TXT Session into a validated,
self-contained transport ZIP and imports that package transactionally into a
new Session directory. The transport package is lossless Session transport; it
is not an HTML publication format.

Public Tcl entry points:

```tcl
::GX::sessionPortableValidate archive
::GX::sessionPortableExport session archive
::GX::sessionPortableImport archive destination
::GX::sessionPortableDependencyDiagnostics packageInfo
```

The GUI exposes Export/Import under Session → Tools and additionally in Projects.

## Package format

The ZIP root contains `gxtxt-session-package.ini` and a `session/` tree. The
package manifest records format version, source GX-TXT version, Session name,
UTC export time, directory/file inventory, SHA-256 and byte size for every
file, classification, module/plugin dependencies, unresolved external
dependencies, and the relocated acquisition source when applicable.

The package manifest describes only the transport container. The Session's own
`metadata/manifest.ini` and registries remain authoritative scientific state.
Stable Dataset, variable, Selection, Temporal Set, interactive document and
other Session IDs are not regenerated by export/import.

## Included and excluded state

The exporter preserves normal Session content, including authoritative
metadata and notes, raw/source files, Datasets, analysis configuration and
results, reports, graphs, provenance and Interactive Document API state.
Calculated artifacts are retained even when recalculation may be possible.

Only files that are unambiguously transient are omitted, such as import/export
staging files, lock/PID files and incomplete `.part` files. Standard Session
directories are represented even when empty.

A regular external scientific source explicitly referenced by the Session
manifest is copied into `raw/portable_source/` when it is not already packaged,
and the imported manifest is relocated to that copy. Arbitrary external
directories, plugin code and machine-global resources are never recursively
copied. Remaining external dependencies are recorded explicitly.

## Dependencies

Plugin/module identities and versions are recorded where determinable. Plugin
executables are not bundled in every Session package. Import preserves Session
data even when a dependency is missing and reports the missing/different
plugin explicitly; it never silently substitutes another module.

## Integrity and security

Import validates the complete archive before commit. It rejects absolute
paths, `..` traversal, duplicate archive paths, symlink archive entries,
undeclared Session files, missing required package/Session manifests and
SHA-256 or size mismatches. Archives are extracted only into a private staging
directory.

Import lifecycle:

```text
validate archive -> stage -> verify Session -> relocate known paths -> atomic commit
```

A failed import removes staging data and leaves no valid-looking partial
Session at the destination. An existing destination is never overwritten.

## Compatibility and relocation

The imported Session becomes a normal independent GX-TXT Session. Known
Manifest Format 2 machine-specific acquisition/runtime paths are relocated to
the new Session root/current framework where required. Stable scientific IDs
and Session-internal portable paths remain unchanged.

The package records the source framework version. Importers should preserve
older compatible Session formats rather than upgrading scientific data merely
for transport.

## Errors

Missing, corrupt or unsafe archives produce explicit errors. Missing plugin or
external-resource diagnostics are returned separately from archive-integrity
failures. A transport package with invalid hashes is never committed.

## dev083 organization and origin

Import issues a fresh organizational Experiment ID and associates Default for Session
Tools, or the selected receiving Project in Projects. Original organizational IDs and
creator are retained as lineage; an import event records the receiver. Scientific IDs
and bytes remain unchanged. Export package carrier_installation is separate from creator.
See [Project Experiment management](PROJECT_EXPERIMENT_MANAGEMENT_API_v1.md) and
[Object Origin](OBJECT_ORIGIN_API_v1.md).

`sessionPortableStageImport archive destination staging` prepares validated transport
in a private unused staging directory while relocating known metadata references to
the final destination. CORE transaction owners commit that staging tree after their
additional membership work. This generic hook uses the same ZIP/inventory/validation
and relocation code; it does not change existing Import's two-argument contract.
