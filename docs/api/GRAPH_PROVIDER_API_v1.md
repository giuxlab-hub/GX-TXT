# GX-TXT Graph Provider API v1

SPDX-License-Identifier: GPL-3.0-or-later

## Purpose

Graph Provider API v1 lets a Standard Module API module declare **which plot types it can offer**. The framework owns selection, persistence, GUI exposure, output-contract assembly and runtime delivery; the module owns the scientific meaning and rendering of each offered plot.

This is distinct from cloning a finished plot. A provider plot is generated by the module from its calculation/cache and can have its own descriptor-driven configuration, legend and annotation capabilities.

## Descriptor contract

```ini
[graphs]
provider_api_version=1
ids=curvefit.family.overlay;curvefit.family.residuals
default_ids=curvefit.family.overlay
rerender=standard_octave

[graph.curvefit.family.overlay]
name=Measured vs fitted curve family
default_enabled=1
file=01_curve_family_fit.png
config_fields=title;x_label;y_label;...

[graph.curvefit.family.residuals]
name=Fit residuals by family
default_enabled=0
file=02_curve_family_residuals.png
config_fields=title;x_label;y_label;...
```

`ids` is the complete set of graph offerings known by the module. `default_ids` selects the offerings enabled in a new experiment. `graph.<id>.default_enabled` can override the default for a single graph.

Each graph ID is a fixed plot type declared by the module. The default/base configuration retains the historical one-per-ID behavior. Since GX-TXT 0.9.7.11, a descriptor may opt into persistent Plot Module API v1 variants with supports_variants=1. Each variant keeps the same graph ID and has an independent variant_id, state and artifact directory. Dynamic graph IDs are not used as instance identifiers. See [Plot Module API v1](PLOT_MODULE_API_v1.md).

## GUI

For an enabled analysis module, Analysis shows every graph offered by the descriptor. Each graph has a `Generate / include this plot` switch followed by its descriptor-generated configuration controls.

A disabled offering is not part of the current experiment and is hidden from the Plots tab even if an older derived PNG is still present on disk.

## Manifest Format 2

The framework stores the selection independently from the graph configuration:

```ini
[graph_provider_api]
version=1
model=module-declared graph types; optional persistent plot variants

[module_graphs.curvefit.family_global]
offered=curvefit.family.overlay,curvefit.family.residuals
enabled=curvefit.family.overlay,curvefit.family.residuals
```

Plot-specific settings remain under:

```ini
[module_plot.curvefit.family_global.curvefit.family.overlay]
...

[module_plot.curvefit.family_global.curvefit.family.residuals]
...
```

## Runtime contract

Before calculation or rerender, the framework writes:

```ini
[graph_provider]
api_version=1
offered=curvefit.family.overlay;curvefit.family.residuals
enabled=curvefit.family.overlay;curvefit.family.residuals
```

The renderer must generate only the graph IDs listed in `enabled`.

## Output contract

The module `[outputs]` section lists non-graph outputs only. The framework appends the `file=` of every enabled graph to the checked output contract automatically.

Example:

```ini
[outputs]
files=fit_parameters.csv;fit_summary.txt;fit_predictions.csv;render_cache.mat
```

If only the overlay graph is enabled, the checked output contract adds `01_curve_family_fit.png`. If residuals are also enabled, it also adds `02_curve_family_residuals.png`.

## Responsibilities

Framework:
- discovers offered graph IDs;
- stores enable/disable state;
- generates the GUI;
- persists selection in the manifest;
- writes runtime selection;
- assembles the checked output contract;
- maps produced PNGs back to graph IDs;
- applies common legend, annotation, export and Print/PDF services.

Module:
- declares plot offerings;
- declares configuration fields and capabilities;
- renders each enabled graph deterministically;
- uses common plot/legend helpers when declaring those capabilities.

## v0.7.2 GUI contract

The Analysis page must present graph offerings compactly. A graph offering is selected separately from its configuration. The standard GUI shows one row per graph with its enabled state, human-readable name, output filename and a `Configure...` action. Plot-specific descriptor fields are edited in a separate dialog. This prevents a module with many graph offerings from making the Analysis page unusable.

For `curvefit.family_global`, both `curvefit.family.overlay` and `curvefit.family.residuals` are enabled by default in a new experiment. Manifest/session loading remains authoritative for an existing experiment.

## Custom module plots

Graph IDs are not predefined by the framework. A Standard Module API descriptor may add any stable graph IDs under `[graphs].ids`. For every ID the module declares `file=`, name, default state, optional configuration fields and common capabilities such as legend and annotation support. The framework does not need a new Tcl branch when a module adds another graph.

The framework supplies common graphics through the global/module inheritance layers; the module renderer remains responsible for the scientific content of each enabled graph.

## v0.9.1 optional region-selection capability

A graph offering may opt in to framework-owned rectangle selection:

```ini
[graph.example]
supports_region_selection=1
region_selection=rectangle
```

The framework owns the UI, data-coordinate conversion, manifest persistence and runtime delivery. The plugin owns the scientific interpretation. Plots without these keys are unchanged.

See `PLOT_REGION_SELECTION_API_v1.md`.

## v0.9.2 reusable selection mapping

Graph providers may extend the v0.9.1 opt-in region selector with:

```ini
region_selection=x_range        ; or rectangle
region_source=primary
region_x_binding=x
region_y_binding=y              ; rectangle only
```

The framework resolves these bindings to canonical Dataset IDs/variables and creates or updates a Dataset Selection API v1 resource. Providers that omit the mapping keep the v0.9.1 plot-region behavior unchanged.

## v0.9.7.11 opt-in plot variants

A graph descriptor may set supports_variants=1. Graph Provider selection and the base graph retain their historical semantics; variants are configured and rendered through Plot Module API v1. A disabled base does not implicitly disable an enabled variant.

## Series Editor provider details

Starting with GX-TXT 0.9.7.21, a Graph Provider can register a provider-owned
details area inside the standard Series editor. Registration, lifecycle,
read-only generic context, base/variant scoping and failure behavior are
defined by [Series Editor Extension API v1](SERIES_EDITOR_EXTENSION_API_v1.md).
The Graph Provider descriptor and Graph Series storage do not acquire
provider-specific presentation fields.

## GX-TXT 0.9.7.22 scheduling projection

Graph Workflow API v1 keeps Graph Provider enabled separate from Plots
USE/NON USE. For base graphs, the standard runtime graph_provider section adds
provider_enabled, use_enabled, and effective_enabled. The legacy enabled field
equals effective_enabled and is the renderer scheduling input. Plot variants
retain their own enabled state independently from the base offering.
