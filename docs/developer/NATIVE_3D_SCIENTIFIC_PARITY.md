# Native 3D scientific capability parity (dev-032)

This inventory compares the frozen `viewer.native_3d` in dev-031 with the public `NATIVE_3D_ENGINE_API_v1` in dev-032. The first table records the verified starting state before the scientific extension; the second table records the completed non-rendering milestone. Those two tables are historical and do not claim GUI migration. The same-version renderer/GUI continuation below records the later presentation state. **COMPLETE** means the relevant non-rendering CORE contract is present; **PARTIAL** means only a narrower contract exists; **MISSING** means no equivalent CORE contract exists; **RENDERING_DEFERRED** means the remaining behavior required the renderer at the earlier milestone; **SUPERSEDED / NOT REQUIRED** means the behavior belongs in the GX-TXT adapter rather than generic CORE.

Evidence paths below are relative to each framework root. `viewer/` abbreviates `plugins/modules/viewer.native_3d/`; `core/` abbreviates `core/native3d/`. The frozen viewer is not modified.

| Legacy capability | Final classification | Evidence and limit |
|---|---|---|
| STL/OBJ source, malformed-index rejection, previews, memory estimate, LOD | COMPLETE | Public import, preview and LOD APIs port the viewer's bounded scans, clustering, decimation and envelope fallback; C tests cover source identity, errors, budgets and derived cache. |
| STEP/XDE hierarchy, shared prototypes and tessellated occurrences | COMPLETE | Public STEP node/instance/mesh and async import APIs retain occurrence transforms, prototype reuse, source SHA, explicit tessellation budgets and corruption-rebuilt derived meshes. Display instancing is separately deferred. |
| VTP polydata and in-memory points, lines, surfaces | COMPLETE | VTP import and polydata constructor expose cells, connectivity and named arrays through the C header. |
| VTU unstructured data and in-memory unstructured grids | COMPLETE | VTU import and unstructured constructor expose ordered cells plus point/cell arrays. |
| VTI image data and in-memory image grids | COMPLETE | VTI import and image constructor expose extent, origin, spacing, direction and named fields. |
| Point/cell scalar and point vector/radius arrays | COMPLETE | Numeric descriptors, value queries and explicit field roles are public, with tuple/association checks. |
| Point clouds, ordered trajectories and tube radius metadata | COMPLETE | Vertex and polyline cells plus point radius/tube radius roles preserve renderer-independent data. |
| Deterministic vector sampling | COMPLETE | Public samples include source point ID, position and vector in local or transformed world coordinates. |
| Explicit scalar-grid isosurfaces and multiple isovalues | COMPLETE | Public image contour API yields a queryable object per nonempty isovalue with a distinct derived fingerprint. |
| Source identity and scientific-derived cache | COMPLETE | XML source SHA is checked before/after import. Nonempty isosurfaces use namespace-scoped, SHA-256-validated atomic cache entries with corruption rebuild. Imported XML source datasets are authoritative inputs rather than cached derived output. |
| Scientific resource limits | COMPLETE | File-byte, geometry, array and 256 MiB minimum decoded-data estimates are checked; in-memory constructors have estimated input budgets. Transient VTK `Update()` peak RSS cannot be enforced by this in-process API. |
| Independent scientific objects, roles, visibility and opacity | COMPLETE | Objects and views are engine/scene scoped; duplicates share immutable source data while presentation state remains independent. |
| Camera, view-local clipping and working-plane state | COMPLETE | Independent view descriptors and headless targets preserve state without producing pixels. |
| Glyphs, visual tubes/arrows, scalar LUT presentation, actual mouse picks | RENDERING_DEFERRED | Requires the later pixel renderer and interaction integration. Public source arrays, samples and API anchors are present. |
| Viewer Provider layer IDs and Session CSV variable-ID interpretation | GUI_INTEGRATION_DEFERRED / SUPERSEDED_NOT_REQUIRED | GX-TXT-specific adapter and persistence belong outside generic CORE. |

The public scientific tests are `test_scientific.c` and `test_scientific_disk_cache.c`. VTK XML import checks advertised geometry/array metadata before loading and validates the dataset immediately after `Update()`, but that blocking call may temporarily exceed estimated memory. The frozen viewer remains the behavioral reference for future rendering, process budgets, and GUI integration.

## Same-version renderer and GUI continuation

The final non-rendering table above records the earlier CORE milestone; its `RENDERING_DEFERRED` and `GUI_INTEGRATION_DEFERRED` rows are superseded by this dev-032 continuation. Public C renderer clients now produce actual RGBA and PNG pixels for VTP/VTU/VTI, point/cell scalar maps and ranges, point or sphere clouds with radius attributes, trajectories/tubes, sampled vectors and multiple explicit isosurfaces. A point scalar opacity role provides per-point alpha independent of object opacity. The renderer uses the authoritative imported/in-memory scientific objects and keeps source arrays unchanged. Its display limits are separate from source-data limits and are recorded in `core/native3d/README.md`.

The additive `viewer.engine_3d` provider maps Session Dataset and Variable IDs to the native scientific constructor, then persists only IDs, roles, source provenance and presentation descriptors. It rerenders from the authoritative Dataset or artifact after SHA checks; it does not serialize bulk point/field payloads in the Session. Real GUI validation covers Dataset points and trajectories together with imported VTP and VTI layers, scalar/vector/radius/tube controls, native picking, Session save/reopen and explicit diagnostics on changed sources. The detailed renderer/GUI capability classification and test evidence is in `docs/developer/NATIVE_3D_RENDERER_PARITY.md`. The frozen legacy viewer remains installed and unchanged.
