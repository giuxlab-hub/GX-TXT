# Tcl rename and source-order stabilization — GX-TXT 0.9.8.10-dev
## Scope and baseline

The 0.9.8.09 audit counted 373 CORE rename operations in its ordered 113-file source simulation. Before this block the current development tree had 466 Tcl `rename` commands: 377 in product Tcl and 89 in test Tcl. This count includes three inline test commands on one line, which a line-leading scan misses. Of the product occurrences, 370 were in files sourced directly by `gxtxt_pipeline.tcl`; seven are in `services/annotations/annotation_api_v1.tcl`, sourced within `module_api_v1.tcl` at line 3002. The exact before/after occurrence ledgers are [RENAME_SOURCE_ORDER_INITIAL_INVENTORY.tsv](RENAME_SOURCE_ORDER_INITIAL_INVENTORY.tsv) and [RENAME_SOURCE_ORDER_INVENTORY.tsv](RENAME_SOURCE_ORDER_INVENTORY.tsv). They record source location, original command, target, affected procedure, top-level load line, textual later-call evidence, chain size, and disposition. The 140 initial product command-name groups are a starting point, not a claim that all are independent semantic families. The audit's 373 count used a narrower scope; it should not be compared directly with 466.

The final inventory contains 89 commands, all in test Tcl; production Tcl contains zero command renames. The current ledger was regenerated by matching every initial command/target pair against the final source and was checked against an independent command-position scan. Its 86 line-leading test commands and three inline test commands all match one ledger row. The initial ledger retains pre-change locations and the original count for review. The 377 production occurrences have all been replaced by explicit named implementations or dispatch, with their old semantic layers preserved as described below. No current occurrence has a pending disposition.

Test renames are isolated fixture instrumentation, including replacement/restoration of Tk dialogs or CORE commands. They are not runtime composition. Their 89 occurrences remain intentionally in 27 test files and 39 affected command-name groups. No Native 3D Tcl command rename appeared in either product inventory; the Native 3D implementation remained frozen.

## `::GX::standardConfigWidget` — pre-change architecture

**Risk:** HIGH. **Classification:** SOURCE_ORDER_EXTENSION_CHAIN. **Occurrences:** ten, at `module_api_v1.tcl:2085,3581,4196,4646,5592`, `dataset_selection_api_v1.tcl:449`, `repeatable_config_api_v1.tcl:550`, `numeric_expression_browser_v1.tcl:99`, `scientific_plot_framework_api_v1.tcl:175`, and `temporal_set_api_v1.tcl:790` (pre-change lines). `module_api_v1.tcl` loads at pipeline line 156, followed by the extension files at 170, 171, 172, 176, and 205. The wrapper chain, outermost to base, is Temporal Set → Unit → Numeric Expression Browser → repeatable table/model → Dataset Selection → Analysis Definition with Parameters/Preflight → generic CSV contract → legacy Analysis Definition → file/path → Boolean → base choice/model/dataset/text. The newer Analysis Definition layer owns that type and shadows only the earlier selector. Every other layer intercepts its own type or delegates to the next. Generic CSV intercepts the specific module/key pair `acq.generic_csv/dataset_kind` independent of descriptor type.

The current caller is `buildStandardConfigFrame`, reached through descriptor-generated Standard Module configuration. The GUI path includes Dataset Expression Browse, FFT Temporal Set selection, scalar model/repeatable configuration, file/path Browse, Unit selection, Dataset Selection, and Analysis Definition Parameters/Preflight. The Session path persists `moduleCfg` through Manifest Format 2; the widgets themselves do not write a Session. Dataset Selection, Temporal Set, and Unit widgets read Session/Dataset metadata when available. The older Analysis Definition implementation and all wrapper command names are retained pending compatibility policy; no current repository Tcl caller outside this family references those names. No Publication is triggered by widget construction, but module execution can consume the resulting configuration.

Before-change focused Xvfb baselines: `test_v092_repeatable_gui.tcl`, `test_v0931_model_selector_gui.tcl`, `test_v0933_gui.tcl`, `test_v078_file_path_gui.tcl` (run with `wish`), and `test_v09775_temporal_set_gui.tcl` passed. The file/path test fails under bare `tclsh` because it does not load Tk; its proper `wish` run passed. Block 3 verified the Numeric Expression Browser GUI and its 79 operations. These checks establish behavior to preserve; they do not by themselves prove a changed implementation.

### Decision and implementation

**Changed.** The ten source-time renames were removed. Each historical target command now receives its implementation under that explicit name at the same source location. A single `standardConfigWidget` dispatcher in `module_api_v1.tcl` selects the owner by the specific generic-CSV module/key pair first, then by normalized descriptor type. Each selected implementation executes once. The old named procedures keep their existing fallback calls so direct internal/programmatic calls retain their historical chain behavior. The older Analysis Definition selector stays callable but normal configuration uses the newer Parameters/Preflight handler. The dispatcher table is the authoritative order; later source files define named dependencies but cannot silently override the entry point. No public API was introduced.

**Post-change checks:** Tcl source/help startup passed at version 0.9.8.10-dev. The five Xvfb GUI baselines above passed unchanged. `tests/test_standard_config_dispatch_gui.tcl` passed: each tested widget took exactly one intended handler, generic CSV used the specific contract editor, current Analysis Definition produced Preflight, the legacy selector stayed callable, and Dataset Expression Browse displayed 79 operations. `tests/test_standard_config_dispatch_demo_gui.tcl` passed against a disposable 4.7 MiB copy of authoritative `DEMO/SESSION/analysis_welch_spectrum_1.0.0`: real GUI startup/open loaded `tset_001`, the Standard Module config frame displayed its Temporal Set, save/reopen restored the binding, and the authoritative manifest hash was unchanged. The copied Session was removed. These tests exercise construction and persistence of the affected widget path; they do not claim full analysis execution or Publication equivalence. No duplicate handler invocation, missing fallback, or unexpected owner was observed in the focused test.

**Current count after this family:** 456 Tcl rename commands: 367 product and 89 test. The ten-command reduction is a consequence of the explicit dispatch, not the acceptance criterion.
