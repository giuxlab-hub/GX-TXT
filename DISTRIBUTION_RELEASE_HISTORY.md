## v0.9.7.66 persistent Project model

Projects are stored as authoritative UTF-8 user state in a small user-local registry following the existing XDG configuration convention. Renaming a Project does not change its ID or memberships. The membership index records stable Experiment IDs plus the last known Session path for navigation, and opening a linked Session refreshes that path without changing Experiment identity.

## v0.6.2 runtime hardening

Standard Octave modules now run through `core/tcl/standard_octave_exec.tcl`. The wrapper streams Octave output, propagates a non-zero child status and verifies every file declared by the module `[outputs] files=` contract. A module cannot be reported as completed if only `runtime.ini` was created.

The generic graphics environment contains only framework-wide `GXTXT_PLOT_*` settings. Historical `GXTXT_IR_*`, `GXTXT_HOLDLED_*`, `GXTXT_COMPARE_*` and fixed ProvaTelecomando node names are not exported to native modules.

The Results tab reads the Canonical Dataset API. `import_result.ini` and `summary.tsv` are legacy Rigol-worker files and are not expected for `acq.generic_csv`.

### v0.6.2 UI/API additions

- Analysis-module plot controls are descriptor-generated and persist through Manifest Format 2.
- Experiment is a small lab notebook with GX-Markup/Markdown Notes, Objective, Procedure/setup and Observations, persisted as `.md` files in the session `notes/experiment/` tree.
- Dataset-ID notes are persisted as `.md` under `notes/datasets/`; Session files can browse them and open them in the common GX-Markup editor.
- Instrumentation is plugin-like: it starts empty and the user explicitly loads an installed Instrument Module API template to create an instrument instance.
- See `PLOT_MODULE_API_v1.md`, `INSTRUMENT_MODULE_API_v1.md` and `MANIFEST_FORMAT_v2.md`.



### v0.6.4 native rerender presentation state

Native rerender no longer reuses a stale `runtime.ini`. Before each rerender the framework regenerates the module runtime from the current GUI state. Standard legend-editor overrides are serialized both in Manifest Format 2 and into `[legend.<graph-id>]` sections of the module runtime. Native renderers pass that runtime configuration to the common `gxtxt_plot_legend()` helper; the session-local TSV/environment path remains only as a compatibility fallback. The analysis log prints the effective native legend override when it is applied.

### v0.6.3 legend integration
Descriptor-defined plots can opt into the shared legend editor with `supports_legend=1` and `legend_editor=standard`. Curve Family Fitting now uses the same editor, click placement, persistence and rerender path as the common graphics framework.

Validation: see `VALIDATION_RESULTS_v064.md`.

### v0.6.9 click-placement hardening

The plot preview cache is explicitly invalidated when a graph is rerendered. `Place legend by click` is covered by a real Tk canvas-event test and manual legend rendering logs the requested and applied normalized position. This avoids the misleading case where the server PNG changed but the Plots tab continued displaying an old in-memory preview.


### v0.6.9 legend manual-position semantics

Real server logs from GNU Octave/gnuplot showed a case where the requested `Position` was stored but the legend still reported `Location=northeast`. Manual placement now disables preset placement explicitly with `Location=none` before committing the final position. The Plots action is named `Place legend center by click...`: the click is the requested legend center in normalized exported-figure coordinates.

### Legend model in v0.6.9

The shared plot editor no longer mixes legend location and entry arrangement. **Placement** (`inside`, `above`, `below`, `left`, `right`, `manual`) is independent from **layout** (`row`, `stacked`, `wrapped`). External legends also have `start / center / end` alignment. GNUplot uses the shared custom legend-axes renderer for deterministic PNG export. The legend font follows the selected global `px`/`pt` unit.



## v0.7.6 Graphics inheritance

Graphics now have an explicit precedence model:

```text
Global graphics
  -> optional Module graphics override
     -> plot-specific override (for example the common legend editor)
```

`Global graphics...` defines DPI, output size and common typography for all native modules. A module keeps those values unless `Module graphics...` is explicitly enabled for that module. Blank/inherit module fields remain global. The common legend editor is the final layer for an individual plot.

Legend size and unit are edited together. Both global and plot-specific legend settings support `px` and `pt`; `inherit` follows the effective parent style.

Graph Provider API v1 remains the module-facing interface for custom plots. A module declares arbitrary stable graph IDs, filenames, defaults, descriptor-generated configuration fields, legend/annotation capabilities and its renderer contract in `module.ini`. The framework owns selection, persistence, runtime delivery, plot discovery, common graphics services and output validation.

# GX-TXT dev-055 — focused Workbench interaction cleanup

Baseline: immutable published dev-054; no second development tree or public intermediate release.

Native2D adds renderer-neutral construction placements (free XY, checked defining reference, earlier placement), resolution/preview, atomic retained creation with existing Coincident relationships, and semantic connectivity. Device acquisition is a host API using the existing control hit authority and effective viewport. Scoped geometry and Python/Octave expose the four non-host operations. No parallel identity, topology, constraint, persistence or solver authority is introduced.

The shared renderer draws retained Points as filled dots; pointer radius remains separate. The same snapshot renderer handles transient Point edit previews. Constraint menus use compact standard Tk cascades, including nested tool-first groups. Dimension strokes are 0.75 px normally / 1.2 px selected versus 1.8 / 3 px model geometry; labels, driven notation, generous hit regions and inline editing retain dev-054 semantics. The command area uses existing responsive Ttk layout. Objects, Points/ranges and View group older commands; More scientific controls exposes the preserved direct controls. Source Dataset Preview remains in View.

Line stays active after committing each independent segment, seeding the next placement with a checked endpoint reference. A segment and its automatic Coincident rules are one history action. Native semantic connectivity determines chain termination on initial/intermediate points; Escape/Finish clears temporary state. Polyline/Spline/Bézier attachments use the same Native transaction. Endpoint coincidence is not periodic spline topology.

Show/Hide and Lock/Unlock use the full current object selection, falling back to the active object. Batch edits restore geometry/history on failure. Publication has explicit combined table/long/wide and reviewed separate output workflows. The existing Publication v2 authority preflights all IDs/paths and wraps existing producers in its existing catalog transaction; a failed create-only batch removes new payloads/metadata and restores registry bytes. Per-output producer identity is retained: primitive publication remains core.native2d, preserving exact reconstruction; other Workbench publication retains its established producer. There is no private Workbench publisher.
